# Packaging `@lefolio/engine`

This repository is both the **lefolio.md website** and the **npm engine**. Site vault (`Content/`) stays in git for Pages; it is **excluded** from the npm tarball via `.npmignore`.

## What gets published

Included (see `package.json` `"files"`):

- `scripts/` — `lefolio` CLI (`bin`)
- `src/` — Next app + templates (tests excluded via `!src/**/*.test.ts`)
- Next/PostCSS/TS config needed to build

Excluded: `Content/`, `public/` (synced assets are generated by `lefolio sync`), `.next/`, `out/`, `.github/`, design notes.

An empty `public/` is created at sync/build time; it does not need to ship in the tarball.

## Local development against the engine

From a thin site (or `lefolio-academic` / `oilandrust.github.io` after migration):

```json
{
  "dependencies": {
    "@lefolio/engine": "file:../lefolio.md"
  },
  "scripts": {
    "dev": "lefolio dev",
    "build": "lefolio build"
  }
}
```

```bash
npm install
npm run dev
```

- Content defaults to `<cwd>/Content` (override with `--content` / `LEFOLIO_CONTENT`).
- If `<cwd>/src/index.ts` (or `.tsx`) exports `TemplateModule`(s), they are registered; select with `Content/config.yaml` `template: <id>`. Override with `--template` / `LEFOLIO_TEMPLATE_ROOT`.
- Next runs from `~/.cache/lefolio/runtime/<version>-<site>` when the engine is installed under `node_modules` (Next cannot transpile app source inside `node_modules`, and parent lockfiles confuse the app root). Developing inside the `lefolio.md` repo uses the repo root directly.
- `lefolio build` copies `out/` back to the site cwd when cwd ≠ the runtime root.

Swap to a released version before publishing the site:

```json
"@lefolio/engine": "0.1.4"
```

Requires Next.js 16 (bundled). Production builds default to `--webpack` for static-export reliability; pass `--turbopack` to opt in.
## Dry-run the tarball

```bash
npm run pack:dry
# or
npm pack --dry-run
```

## First npm publish (maintainers)

1. Create/join the npm org **`lefolio`** (matches `@lefolio/engine`).
2. `npm login`
3. Confirm package contents: `npm pack --dry-run`
4. From a clean tree on `main`:

```bash
npm publish --access public
```

(`publishConfig.access` is already `public` for the scoped name.)

5. Tag the release: `git tag v0.1.0 && git push origin v0.1.0`

Bump `"version"` in `package.json` for each release (semver).

## CLI entry

```text
npx @lefolio/engine …     # after publish
npx lefolio …             # when bin is linked via dependency
node scripts/lefolio.mjs  # inside this repo
```

Commands: `sync` | `dev` | `build`. Extra flags after the command (e.g. `--turbopack`) are passed to Next.
